# Learning Reflection | APIs + RSS for DeRexi Pulse

## What I set out to learn
How software collects current public information from organizations without copying pages by hand, and how that information can support a fintech policy governance workflow.

## What I can now explain
An API lets systems communicate with a defined request and response, often using HTTP and JSON. RSS is an XML feed listing newly published content. The tools overlap because programs can retrieve RSS over HTTP; however, they have different purposes. An API can support complex searches and filters, while RSS provides a consistent stream of publication metadata.

## How this changes DeRexi
Pulse can collect updates from official government sources and display them in a clean, source-linked feed. This is the beginning of a review process, not an automated claim of legal applicability. The owner can investigate a new item and decide whether existing policies require attention.

## Most important lesson
**Seeing an update is not the same as understanding a requirement.** The date, publisher, type, and original link matter as much as the headline. Responsible implementation includes error handling, source attribution, and honest evidence.
